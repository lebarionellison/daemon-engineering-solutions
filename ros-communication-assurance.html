01 / LIVE TEST COVERAGE

TEST COMPATIBILITY, NOT JUST CONFIGURATION FILES.

The probe starts real ROS 2 publisher/subscriber endpoints under the selected RMW implementation. Positive tests must exchange messages; negative tests must surface an incompatible-QoS event and must not deliver samples.

01 · RELIABILITY

Reliable ↔ Reliable

Confirm reliable publisher and subscriber endpoints match and exchange samples.

02 · REQUEST / OFFER

Reliable → Best Effort

Confirm a reliable offer satisfies a best-effort request.

03 · NEGATIVE TEST

Best Effort → Reliable

Expect an incompatible-QoS event when a best-effort offer cannot satisfy a reliable request.

04 · DURABILITY

Transient Local Retention

Join after publication and confirm a transient-local subscriber receives retained samples.

05 · DURABILITY

Transient Local → Volatile

Confirm a transient-local offer satisfies a volatile request.

06 · NEGATIVE TEST

Volatile → Transient Local

Expect incompatibility when a volatile offer cannot satisfy a transient-local request.

02 / EXECUTION

RUN IT IN THE CUSTOMER'S ROS ENVIRONMENT.

Source the intended ROS distribution and select an installed RMW implementation. The command runs all six scenarios and writes a JSON report.

LOCAL ROS 2 ENVIRONMENT
source /opt/ros/$ROS_DISTRO/setup.bash

python3 ros2/communication_assurance/qos_probe.py \
  --scenario all \
  --duration 3 \
  --output daemon-ace-communication-report.json

# Optional middleware selection
RMW_IMPLEMENTATION=rmw_cyclonedds_cpp \
  python3 ros2/communication_assurance/qos_probe.py --scenario all
The probe exits 0 only when each selected scenario matches its expected behavior. An incompatible pairing is an expected negative test—not a failure—when the middleware reports the incompatible-QoS event and no samples are delivered.

04 / EVIDENCE CONTRACT

VERSIONED RESULTS WITH EXPLICIT LIMITS.

Each report records ROS_DISTRO, RMW_IMPLEMENTATION, ROS domain settings, each scenario's expected and observed outcome, publisher/subscriber policy, message counts, incompatible-QoS events, and local timing observations.

REPORT CONTRACT
{
  "schema": "daemon-ace.ros2-communication-assurance.v1",
  "report_version": "1.0.0",
  "environment": {
    "ros_distro": "jazzy",
    "rmw_implementation": "rmw_fastrtps_cpp"
  },
  "summary": {
    "scenarios_total": 6,
    "scenarios_passed": 6,
    "scenarios_failed": 0,
    "disposition": "PASS"
  }
}
Latency is a same-host monotonic publish-to-callback diagnostic, not synchronized one-way network latency or a real-time guarantee. This release does not test multi-host networks, exhaustive DDS discovery/security/fault behavior, simulation, physical robots, functional safety or production fleets.
