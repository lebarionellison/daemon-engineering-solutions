## Stripe payment verification (live checkout remains disabled)

DAEMON ACE's two Stripe catalog products and payment links exist in the connected Stripe account. The payment links are intentionally inactive until secure fulfillment is complete.

### Worker configuration

In Cloudflare Dashboard, open **Workers & Pages → daemon-engineering-solutions → Settings → Variables and Secrets** and add the following as an encrypted secret:

- `STRIPE_WEBHOOK_SECRET` — the signing secret generated by the Stripe webhook endpoint.

Do not place the secret in GitHub source, browser JavaScript, a public environment variable, or a chat message.

The Worker expects Stripe events at:

`https://daemon-engineering-solutions.lebarionellison.workers.dev/api/stripe/webhook`

Configure the Stripe webhook endpoint to send only:

- `checkout.session.completed`
- `checkout.session.async_payment_succeeded`

The endpoint verifies the Stripe-Signature HMAC against the raw request body, rejects stale signatures, accepts only paid USD Checkout Sessions matching the two catalog product codes and exact amounts, and records the event/session in D1 with unique constraints for idempotency.

### D1 migration and deployment

The GitHub Actions deployment workflow applies pending D1 migrations remotely before deploying the Worker. Confirm the workflow completes successfully before creating the Stripe webhook endpoint.

After deployment:
1. Create the live-mode Stripe webhook endpoint using the URL above and the two event types listed above.
2. Copy its signing secret into the Cloudflare encrypted Worker secret named `STRIPE_WEBHOOK_SECRET`.
3. Redeploy/restart the Worker if required by the Cloudflare dashboard.
4. Send a Stripe test webhook only in a test-mode endpoint/account first if available; the connected Stripe account currently used for catalog creation is live mode.

### Fulfillment status

A verified payment is recorded as `pending_secure_fulfillment`. This code does **not** yet issue download links, create customer entitlements, or deliver bundle files. Do not activate the payment links until the actual bundle artifacts and short-lived, per-purchase download delivery are implemented and tested. No shared DAEMON ACE generation token is exposed to buyers.
